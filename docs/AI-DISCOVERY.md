# Публичные данные для браузерных помощников

## Источники и статус

Реализация проверена по первоисточникам 16 октября 2026 года:

- [Спецификация WebMCP](https://webmachinelearning.github.io/webmcp/) и [документация Chrome](https://developer.chrome.com/docs/ai/webmcp/imperative-api): текущий API `document.modelContext.registerTool`, JSON Schema, аннотации и очистка через `AbortSignal`. Для ранних браузерных реализаций поддержан `navigator.modelContext` и `unregisterTool`.
- [llms.txt v2](https://llmstxt.org/): Markdown с H1, кратким описанием в цитате, пояснениями и разделами H2 со списками ссылок. Для обнаружения добавлена ссылка `rel="describedby"` в HTML.
- [AI Catalog 1.0](https://ai-catalog.io/spec/): черновик формата с `specVersion`, `entries`, идентификаторами и ровно одним из `url`/`data`. Каталог размещён в корне и `/.well-known/`; HTML содержит `rel="ai-catalog"`.

WebMCP и AI Catalog продолжают развиваться. Наличие файлов не гарантирует использование поисковыми системами. `llms.txt` не заменяет robots.txt и не управляет правами. `webmcp.json` — собственное описание инструментов приложения; оно явно не объявляется HTTP MCP-сервером или отдельным общим стандартом.

## Состав

| Файл | Назначение |
| --- | --- |
| `src/ai/publicTools.ts` | Поиск и схемы шести инструментов чтения |
| `src/ai/registerWebMcp.ts` | Регистрация, совместимость и очистка |
| `src/components/WebMcpBridge.web.tsx` | Подключение к актуальному публичному DataProvider |
| `scripts/ai-discovery.ts` | Общая генерация обзора, каталога и описаний |
| `public/llms.txt` | Краткий обзор и ссылки |
| `public/ai-guide.md` | Руководство, примеры и ограничения |
| `public/ai-catalog.json` | Каталог публичных ресурсов |
| `public/.well-known/ai-catalog.json` | Точная копия для обнаружения на уровне домена |
| `public/webmcp.json` | Описание WebMCP, имена и JSON Schema параметров |

При `npm run build:web` файлы в `dist` генерируются из того же снимка данных, что и статические страницы. Для обновления исходных файлов в `public` из `cms/seed/content.json`: `npm run ai:generate`. После изменения инструментов обновляйте исходные файлы этой командой. Генерация не требует ключей.

Nginx выдаёт каталоги как `application/ai-catalog+json`, обзор — `text/plain`, руководство — `text/markdown`; для отсутствующих файлов возвращает 404. Локальный preview использует такие же MIME-типы. Отдельное правило robots.txt разрешает `/api/data`, сохраняя запрет остального `/api/` и `/admin`.

## Инструменты и границы

Все инструменты имеют `readOnlyHint=true`, `untrustedContentHint=true`, `consequentialHint=false`:

- `uletay_get_festival`: даты, место, текущий выпуск, годы архива.
- `uletay_find_artists`: имя и год; по умолчанию текущий выпуск.
- `uletay_find_events`: выступления или автограф-сессии в пределах текущего фестиваля; дата и сцена.
- `uletay_find_food`: точки питания и меню.
- `uletay_find_map_places`: публичные объекты; служебные зоны с запретом доступа исключены.
- `uletay_get_rules`: опубликованные правила посещения.

Лимит результатов — 1–50, по умолчанию 10. Неизвестные параметры, неверные даты, категории и типы отклоняются. Ответ включает источник, редакцию, время получения, признак кеша/встроенных данных и ссылки на страницы. Пустое расписание не заполняется прошлыми выступлениями. Время — Europe/Samara. Демо-режим не меняет ответы.

Сессии и действия админки, избранное, сохранённые места, геолокация, отправка уведомлений и билеты инструментам не передаются. В неподдерживаемом браузере регистрация пропускается без влияния на интерфейс. Нативные сборки используют пустой компонент.

## Проверка

```sh
npm run test:ai
npm run check
npm run build:web
PORT=4174 npm run preview
curl -i http://localhost:4174/llms.txt
curl -i http://localhost:4174/.well-known/ai-catalog.json
curl -i http://localhost:4174/webmcp.json
TEST_WEB_ORIGIN=http://localhost:4174 npm run test:ai:http
```

Тесты проверяют поиск, текущий год и архив, даты, безопасное кодирование ID в ссылках, свежесть данных, отсутствие изменений контента, ошибки ввода, отмену, жизненный цикл современного и раннего API, отсутствие поддержки, запрет регистрации браузером и генерацию файлов. При сборке дополнительно проверяются файлы и discovery-ссылки во всех индексируемых HTML.

Для проверки настоящего браузерного API нужен Chrome с поддержкой WebMCP. Условия доступа меняются; используйте [текущую инструкцию Chrome](https://developer.chrome.com/docs/ai/webmcp). Откройте локальное приложение и в панели разработчика проверьте `await document.modelContext.getTools()`. Отсутствие API означает отсутствие поддержки или разрешения браузера, а не ошибку страницы. Не включайте флаги и не подключайте origin trial к рабочему домену без отдельной настройки выпуска.

## Результат локальной проверки 16 октября 2026

Пройдены `test:ai`, `check`, полный `npm test`, экспорт Web/iOS/Android и проверка 301 URL в sitemap. HTTP-проверка на отдельном локальном preview с production CSP подтвердила 16 ссылок из llms.txt, обе копии каталога, MIME, JSON, HTML-ссылки обнаружения, robots.txt и чтение локального API.

Регистрация, вызовы, отмена и очистка проверены в изолированном окружении, имитирующем современный и ранний браузерный API. Реальный вызов агентом в браузере с WebMCP не подтверждён; это отдельная проверка совместимости. Флаги браузера, origin trial и рабочий сервер не менялись.

При проверке устранено падение preview-сервера при отсутствии файлов во время пересборки: теперь ответ 503 временный, после появления index.html сервер продолжает работу. Отсутствующий discovery-файл возвращает 404, а не HTML приложения. Оба сценария воспроизведены на отдельном локальном экземпляре.
