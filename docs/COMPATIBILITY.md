# Совместимость с установленными приложениями

Проверено локально 16 октября 2026 года. Публикация, магазины и рабочая БД не изменялись.

## Вывод

Для проверенного контракта API несовместимостей не обнаружено. Обновление сайта и CMS не заменяет JavaScript или нативные библиотеки в уже установленных Google Play/RuStore-приложениях. В текущем проекте нет зависимости `expo-updates` и адреса OTA-обновлений; workflow выпуска собирает и разворачивает web/CMS, не публикует OTA или пакеты магазинов. WebMCP и discovery-файлы не добавляют требований к мобильным клиентам.

Установленные версии продолжают обращаться к тому же `/api`. Сохранены анонимное чтение, обязательные поля JSON, идентификаторы, типы и значения категорий, форматы push, URL изображений и метаданные радио. Миграция доступа добавляет поля только административным пользователям. Старой браузерной сессии администратора может потребоваться повторный вход; мобильные посетители не используют эту авторизацию.

Загрузчики старых выпусков выполнялись в Node с имитацией платформы Android и AsyncStorage, но с их настоящими функциями загрузки, нормализации и валидации. Запросы направлялись к новой standalone CMS на localhost. Для реалистичного набора данных публичный рабочий каталог и изображения скопированы в изолированную тестовую БД и uploads. Рабочий сервер только читался.

Это не запуск магазинных APK на устройстве. В этом прогоне не проверялись доставка настоящего push провайдерами, звук через динамик и нативные экраны после обновления сервера. Текущий статус распространения версий в магазинах не запрашивался: использованы сохранённые выпуски.

## Ранее отсутствующее изображение

`/api/uploads/images/отава-ё-fdb2e96f699a.webp` возвращает 404 и на рабочем сайте. Новая CMS не создаёт эту проблему; клиент показывает заглушку изображения. В сравнении с рабочим сервером это отдельно отмечено как существующий дефект, а не успешная загрузка. Исправление фотографии в рабочем контенте не выполнялось.

HTTP-тест по умолчанию требует доступности всех изображений. При явном `TEST_MEDIA_BASELINE_ORIGIN=https://uletayapp.ru` он сверяет отсутствующие файлы с рабочим сервером; допускается только совпавший прежний 404, новые 404 и все остальные ошибки останавливают тест.

## Условия совместимого развёртывания

1. Сохранить домен `uletayapp.ru`, маршруты `/api/*`, существующую БД и uploads. Обновлять имеющийся сервер через `cms:migrate`; не запускать повторное заполнение контента из seed. Миграция выполняется до запуска новой CMS.
2. Переносить действующие `.env`, ключи и идентификаторы Expo/FCM/RuStore и пару VAPID. Не заменять их новыми значениями при переносе. Скрипт релиза использует общие uploads и сохраняет прежнюю конфигурацию.
3. Выпускать web/CMS отдельно от Android APK/AAB и любых OTA. Нативный выпуск с обновлёнными зависимостями требует собственной проверки; его нельзя объявлять проверенным лишь по web-сборке.

Не переименовывать и не удалять старые обязательные поля, ID объектов и endpoint без сохранения старого контракта. Новые возможности добавлять необязательными полями. Если понадобится несовместимый формат, вводить отдельную версию API, сохраняя `/api` для установленных клиентов.

## Повторная проверка

```sh
npm run test:compat
TEST_API_ORIGIN=http://localhost:3107 npm run test:compat
TEST_API_ORIGIN=http://localhost:3107 TEST_MEDIA_BASELINE_ORIGIN=https://uletayapp.ru npm run test:compat
```

Вторая и третья команды читают локальную CMS. Все HTTP-операции этого теста только GET/OPTIONS. PowerShell: сначала задайте переменные через `$env:TEST_API_ORIGIN='http://localhost:3107'` и `$env:TEST_MEDIA_BASELINE_ORIGIN='https://uletayapp.ru'`.

Для полного повторения теста старых загрузчиков доступна `npm run test:compat:releases`. `RELEASE_CLIENT_SOURCES` — JSON-массив объектов `{ "version": "1.0.15", "source": "<архив>/1.0.15/source", "hashes": "<архив>/1.0.15/source-hashes.json" }`. Для снимка из Git вместо `hashes` укажите `gitCommit`. Старые архивы не включены в обычную поставку исходников; источник нужно передать явно. Файл результатов создаётся в `tmp/native-release-compat-results.json`.

Источники поведения Expo: [runtime versions](https://docs.expo.dev/eas-update/runtime-versions/) и [устройство EAS Update](https://docs.expo.dev/eas-update/how-it-works/).
