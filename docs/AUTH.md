# Вход и доступы

## Владелец

При `cms:install` создаётся локальная учётная запись из `ADMIN_USER` и `ADMIN_PASSWORD`. Пароль хранится как bcrypt-хеш. При миграции существующие локальные администраторы получают роль `owner`; пароли сохраняются. Повторный `cms:install` меняет пароль только указанного `ADMIN_USER` и закрывает его серверные сессии.

Владелец управляет контентом, отправками и разделом «Доступы». Через интерфейс невозможно отозвать доступ владельца и случайно оставить проект без управления. Создание дополнительных владельцев — задача администратора сервера.

## VK ID

Используется OAuth с PKCE. Приложение запоминает случайный `state` и verifier в зашифрованной HttpOnly-cookie на 10 минут. После возврата сверяет состояние, обменивает код на сервере и получает VK ID через `user_info`. ID из адресной строки не считается подтверждением личности.

Сервер допускает только активный VK ID из `admin_users`. Автоматической регистрации всех пользователей VK нет. Токены VK не хранятся в браузере, базе или журналах.

Настройка:

1. В кабинете VK ID откройте приложение «Такси Грахово». Его публичный ID находится в `VK_APP_ID` настроек такси.
2. Добавьте домен `uletayapp.ru` и точный Redirect URI: `https://uletayapp.ru/admin/auth/vk/callback`. Для другого домена замените хост.
3. Сохраните существующие адреса такси. Для локальной проверки отдельно добавьте `http://localhost:3000/admin/auth/vk/callback`, если кабинет разрешает localhost.
4. Укажите `VK_APP_ID` и `VK_REDIRECT_URI` в `cms/.env`, затем перезапустите CMS. В GitHub Actions это Variables окружения `production`.
5. Войдите владельцем и добавьте числовой VK ID в разделе «Доступы». Короткое имя профиля не подходит.
6. В отдельном приватном окне пройдите вход через VK и проверьте доступ.

Для входа не нужны пользовательский API-токен владельца, токен сообщества, телефон и секрет Mini App. В локальном `cms/.env.local` подготовлен публичный ID из конфигурации такси; локальные настройки в архив исходников не попадают. Настройку домена в кабинете VK ID в ходе подготовки подтвердить не удалось.

Обработчики: `/admin/auth/vk` и `/admin/auth/vk/callback`. Отказ пользователя, неправильный или просроченный state и неизвестный VK ID возвращают ошибку на страницу входа.

## Сессии

Cookie защищена iron-session, флагами HttpOnly и SameSite=Lax; в production требуется HTTPS. В MySQL хранится SHA-256-хеш случайного токена сессии. Сессия действует до семи дней. Каждый защищённый запрос проверяет сессию и активность пользователя в БД.

Отзыв VK-доступа выключает пользователя и удаляет все его сессии. Возврат доступа не восстанавливает прежние сессии. При выходе удаляется текущая серверная сессия и cookie. Старые cookie без серверного токена больше не действуют: после обновления нужно войти заново.

`POST /api/auth` выдаёт Bearer-токен для технических операций по логину и паролю. Он разрешает операции API с контентом, но не управление доступами. Частота попыток входа ограничена в памяти процесса. Для нескольких экземпляров CMS потребуется общий лимитер, например Redis.

Протокол: [официальный VK ID SDK](https://github.com/VKCOM/vkid-web-sdk). Проверки доступа: [рекомендации Next.js](https://nextjs.org/docs/app/guides/authentication).
