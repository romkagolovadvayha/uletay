# Архитектура

## Границы системы

В репозитории два приложения с отдельными `package-lock.json`. Корень — Expo-клиент; `cms` — Next.js-сервер и админка. Это позволяет обновлять сервер отдельно от мобильных пакетов.

```text
Браузер / Android / iOS
        │ HTTPS
        ▼
nginx ───────► dist/ (статическая web-сборка)
        │ /admin, /api, /_next
        ▼
Next.js CMS ─► MySQL
        ├────► uploads/ (изображения редакторов)
        └────► внешние API (VK ID, Last.fm, push, радио, маршруты)
```

## Данные

Содержимое фестиваля хранится единым JSON-документом в `app_content`, строка `id=1`. Это действующая модель проекта: коллекции небольшие, редактирование выполняет команда фестиваля. `cms/seed/content.json` применяется только при установке на пустую БД. Актуальные правки редакторов находятся в MySQL, а не в seed.

Путь чтения: `src/api/appDataApi.ts` → `GET /api/data` → `cms/src/lib/app-data.ts`. Публичная версия очищается от служебных данных. Контент проверяется общим модулем `shared/app-data-validation.ts`.

Сохранение выполняется с ревизией исходного документа. Два редактора не могут незаметно затереть изменения друг друга: устаревшая ревизия отклоняется. Кеш CMS проверяет ревизию БД; клиент сохраняет данные для работы без сети. Избранное и настройки хранятся на устройстве. Подписки push и история отправки — в отдельных таблицах MySQL.

Если объём контента или число одновременных редакторов значительно вырастет, коллекции можно перенести в отдельные таблицы. При этом нужно сохранить публичный контракт `/api/data` для уже установленных мобильных версий.

## Админка

- `page.tsx` выбирает раздел по `tab` и проверяет текущего пользователя.
- `components` содержит редакторы по разделам. `EditorForm` отвечает за несохранённые изменения и состояние отправки.
- `actions.ts` сохраняет контент; `auth-actions.ts` отвечает за вход, выход и доступы.
- `lib/admin-navigation.ts` задаёт разделы и поиск.
- `styles/base.css` содержит базовые элементы и редакторы; `workspace.css` — компоновку; `theme.css` — общие цвета и состояния светлой/тёмной темы. Новые цвета задавайте через `--admin-*`.
- Ошибки подключения к БД показывает `admin/error.tsx`.

Права проверяются на сервере в действиях и API. Скрытие кнопки не служит проверкой доступа. Подробности — в [AUTH.md](AUTH.md).

## Карта и медиа

`src/components/map` разделяет общую сцену и платформенные рендереры MapLibre. Маршруты по площадке учитывают ограждения и закрытые зоны. Исходная геометрия и генераторы — в `scripts/festival-map-*`, снимок приложения — в `src/data/festivalMapSnapshot.json`. Перед изменением геометрии прочитайте [описание редактора](admin-map-editor.md).

Загрузки редакторов проходят проверку и преобразование Sharp. Файлы хранятся вне сборок, в `uploads`. Публичные изображения выдаёт общий модуль `lib/public-images.ts`: разрешённые форматы, проверка пути и символьных ссылок. Каталог `assets` содержит медиа исходников; его также использует `/api/fest-assets`.

## Сборка и обновления

`build:web` экспортирует Expo и создаёт HTML публичных маршрутов, sitemap и PWA-файлы. `cms:build` собирает standalone Next.js и копирует статические файлы. `deploy` содержит ручной запуск и выпуск через GitHub Actions с отдельными каталогами релизов.

При обновлении сохраняются MySQL, `uploads` и ключи окружения. `db:migrate` меняет только схему. Скрипты импорта и `map:migrate-production` изменяют содержимое; запускайте их отдельно, понимая назначение и имея резервную копию.
