# Улетай радио: источник и проверка

Звук: `https://r1.prostoj.store/station-6.mp3` (liscase, «Рок станция»).
Метаданные: публичный API liscase `/v1/radio/state?id=6`, через CMS Улетай
`/api/radio/now-playing`. Источник и ID заданы в `src/config/radio.ts`.
Старые ICY-источник и резервное обращение к прежней радиостанции удалены.

CMS проверяет ответ, объединяет одновременные обращения, кэширует на 3 секунды,
прерывает зависший запрос через 8 секунд. Ошибки возвращаются как 502 с
`Cache-Control: no-store`. Приложение опрашивает эфир раз в 3 секунды, только
когда раздел открыт или радио играет; повторные запросы объединяются.
При ошибке очередь скрывается, последний трек помечается как устаревший.
Остановка и повторное включение заново подключают к прямому эфиру.

Обложка liscase приоритетнее фотографии участника фестиваля. Исполнитель,
название и обложка передаются также в системный плеер Android/iOS. Избранное
хранится локально; ссылка «Поделиться» ведёт на `/playlist` приложения.

Джингл приходит с `kind: "jingle"`, собственными `title` и `artworkUrl`.
Для него не подбирается артист фестиваля, не показывается поиск музыки и
недоступно добавление в избранное. Экран использует надпись «Пауза между
песнями» и заданный администратором логотип. Парсер сохраняет `kind` через CMS
и дополнительно исключает джинглы из очереди и предыдущего трека.
Порядок и интервал джинглов задаются в админке liscase `/radio/jingles?id=6`.

SEO: постоянный canonical `/playlist`, статический HTML с H1 и описанием,
Open Graph/Twitter, sitemap и JSON-LD RadioBroadcastService/ListenAction.
Новый радиодомен разрешён в production CSP. Регистрация для эфира не нужна.

Проверки:

```sh
npx tsx --test scripts/test-radio.ts
npm run typecheck
npm run build:web
npm run cms:build
npm run seo:check
```

Локальное превью с настоящим API и production CSP (PowerShell):

```powershell
npm run cms:dev
# В другом терминале:
$env:PREVIEW_API_ORIGIN = 'http://localhost:3000'
$env:PREVIEW_PRODUCTION_CSP = '1'
npm run preview
```

Открыть `http://localhost:4174/playlist`: запуск/остановка/повторный запуск,
обложки, смена трека, очередь, избранное после перезагрузки и ширины 320–1440 px.
Серверный прогресс приблизительный: у слушателя возможна задержка MP3-буфера.
Проверка браузера не заменяет тест фонового воспроизведения на физическом телефоне.
