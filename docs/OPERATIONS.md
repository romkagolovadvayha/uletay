# Эксплуатация и перенос данных

## Что хранить

Для восстановления нужны **вместе**: исходники нужной версии, дамп MySQL, каталог `uploads`, серверный `cms/.env`, настройки сборки клиента и ключи внешних сервисов. `cms/seed/content.json` не заменяет дамп рабочей БД. При выдаче компании доступа заранее назначьте владельцев сервера, домена, БД, VK ID и кабинетов магазинов.

Подписание Android/iOS требует прежних ключей. Замена ключа Android без процедуры магазина может сделать обновление невозможным. Ключи, Firebase/FCM, RuStore Push, Apple/EAS и служебные учётные записи передаются отдельно от исходников.

## Резервная копия

На время окончательного переноса остановите редактирование в админке и задания отправки напоминаний. Для небольшого проекта проще остановить CMS, сделать согласованную копию, затем запустить её снова. Если используются релизы GitHub Actions, рабочая папка — `/var/www/uletay/current`, а загрузки — `/var/www/uletay/uploads`.

```sh
mkdir -p /var/backups/uletay
chmod 700 /var/backups/uletay
mysqldump --single-transaction --hex-blob -h 127.0.0.1 -u uletay -p uletay > /var/backups/uletay/database.sql
tar -czf /var/backups/uletay/uploads.tar.gz -C /var/www/uletay uploads
cp /var/www/uletay/cms/.env /var/backups/uletay/cms.env
chmod 600 /var/backups/uletay/*
```

В схеме релизов путь последней команды — `/var/www/uletay/current/cms/.env`. Копии содержат секреты и данные подписок: храните их с ограниченным доступом и проверяйте восстановление на отдельной БД.

На новом сервере после создания БД:

```sh
mysql -h 127.0.0.1 -u uletay -p uletay < database.sql
tar -xzf uploads.tar.gz -C /var/www/uletay
cd /var/www/uletay
npm run cms:migrate
```

Восстановите `cms/.env`, поправьте подключение и абсолютные пути. Сохраните VAPID-ключи: их замена нарушит существующие web-push подписки. Сначала проверьте новый сервер, затем переключайте DNS. Для мобильных версий желательно сохранить прежний домен API.

## Обычное обновление

Для ручной установки: сделайте резервную копию, обновите исходники, выполните `npm ci` в корне и CMS, `npm run cms:migrate`, `npm run build:web`, `npm run cms:build`, затем `pm2 restart uletay-cms --update-env`. Не запускайте первоначальную установку и скрипты импорта при каждом обновлении.

На рабочем сервере предпочтительна схема с отдельной папкой релиза и переключением после проверки: она уже реализована в [GitHub Actions](../deploy/README.md). Ручная сборка поверх работающей папки может кратковременно затронуть открытые web-сессии.

Откат: верните предыдущую сборку и её конфигурацию. Аддитивная миграция доступа не удаляет прежние столбцы. Если обновление меняло содержание, восстанавливайте согласованную резервную копию БД и файлов; простой откат кода не откатывает правки контента.

## Фоновые задачи

Напоминания об избранных выступлениях отправляются отдельной командой каждую минуту. После настройки push-ключей:

```sh
sudo env DEPLOY_PATH=/var/www/uletay bash deploy/setup-push-reminders-cron.sh
```

Проверьте `/etc/cron.d/uletay-push-reminders` и журнал, путь к которому указан в нём. Last.fm синхронизируется workflow `.github/workflows/sync-lastfm.yml`; на новом сервере без GitHub Actions можно запускать `npm --prefix cms run headliners:sync-lastfm` вручную после заполнения ключа. Не запускайте обе схемы одновременно. Автоматический поиск/замена изображений — отдельная операция импорта.

Для каждого интеграционного сервиса проверьте лимиты и владельца доступа: VK ID, Last.fm, Expo Push/FCM/APNs, RuStore Push, Web Push, картографические сервисы и источник радио. [Описание радио](radio-liscase.md).

## Диагностика

```sh
pm2 status
pm2 logs uletay-cms --lines 100
curl -f http://127.0.0.1:3000/api/health
sudo nginx -t
sudo systemctl status mysql nginx cron
sudo certbot renew --dry-run
```

В схеме релизов имя процесса и активный порт записаны в `.active-process` и `.active-port` в `/var/www/uletay`. `/api/health` проверяет доступность БД; `/api/data` — чтение контента. HTTP 502 обычно означает, что CMS не запущена или nginx направляет запрос на другой порт.

Вход есть, контента нет — проверьте выбранную БД и `app_content`. Изображения не открываются — пути `UPLOAD_DIR`, `REPO_ASSETS_DIR` и права чтения/записи. Не работает VK — точное совпадение Redirect URI в серверных настройках и кабинете VK ID. Смена `ADMIN_PASSWORD` в `.env` сама по себе не меняет хеш в БД; для контролируемого сброса используйте `cms:install` с нужным `ADMIN_USER`.
