# Деплой и синхронизация через Gitlub

Репозиторий: https://gitlub.prostoj.store/romkagolovadvayha/uletay.
Push в `master` запускает `.forgejo/workflows/deploy.yml`.
В том же релизе публикуется `https://vk-headliners.uletayapp.ru`: страница
`cms/src/app/vk-headliners` получает всех участников текущего года из CMS.
Порядок совпадает с сортировкой приложения по популярности: слушатели Last.fm,
затем прослушивания, затем имя. Общая реализация — `shared/headliner-popularity.ts`.
Подпись и адрес VK Музыки редактируются в карточке артиста.
Страница Mini App показывает карточки артистов и две нижние кнопки: всех участников
и покупки билета. Шапка, даты, возрастная отметка, таймер и дополнительный футер удалены.
Nginx направляет корень поддомена на `/vk-headliners` того же нового CMS-процесса.
Автодеплой выпускает отдельный сертификат Let's Encrypt для `vk-headliners.DOMAIN`
через webroot (A/AAAA должны указывать на production), сохраняет hook перезагрузки
nginx при продлении и проверяет страницу, JS/CSS, HTTPS и разрешение встраивания
во ВКонтакте. Ошибка останавливает выпуск и откатывает общую конфигурацию nginx.
Админка на поддомене недоступна. Существующий запрет встраивания основного сайта
и админки сохраняется. Для запуска внутри VK Mini Apps укажите этот HTTPS URL
в настройках соответствующего приложения VK; публикация сайта не создаёт приложение VK.

Выделенное приложение витрины — **54834082**, тестовое сообщество — **242402250 (TEST)**.
В настройках платформ приложения укажите `https://vk-headliners.uletayapp.ru/`
и разрешите добавление в сообщества. Это отдельное приложение: `VK_APP_ID`,
секреты VK ID для входа в CMS и ключи других приложений менять не нужно.
Установка открывается по `https://vk.com/app54834082#setup`; панель показывается
только с `#setup`, в том числе администратору TEST. Кнопка вызывает
`VKWebAppAddToCommunity`, затем `VKWebAppShowCommunityWidgetPreviewBox`.
Ответ preview `result=true` означает только открытие предпросмотра;
публикацию нужно подтвердить в окне VK и проверить на странице сообщества.

Нативный шаблон `tiles` содержит до десяти самых популярных участников,
те же фотографии из CMS, что и сайт, жанры и ссылки на VK Музыку.
Для VK исходники обрезаются по центру до квадрата и загружаются в коллекцию
приложения: `160x160` для плиток и `50x50` для компактного списка (до шести строк).
Файлы отправляются с тройным разрешением, как требует VK. Перед загрузкой используется
JPEG MozJPEG с качеством 72 и цветовой субдискретизацией 4:2:0; метаданные удаляются.
ВК перекодирует изображения, поэтому итоговый вес нужно проверять по вариантам,
возвращаемым `appWidgets.getImagesById`. Доставкой этих файлов управляет CDN ВК.
Привязка исходного URL, SHA-256, профиля сжатия, веса загружаемых файлов и публичных ID
находится в `shared/vk-widget-images.json`. Смена профиля сжатия также вызывает загрузку.
После изменения фотографий выполните `node cms/scripts/sync-vk-widget-images.mjs`
с переменной окружения `VK_WIDGET_SERVICE_TOKEN` — сервисным ключом приложения
54834082. Скрипт проверяет принадлежность ключа, пропускает неизменившиеся файлы,
сохраняет результат каждой загрузки и допускает повторный запуск после сбоя.
Для проверки одного артиста можно передать его ID аргументом команды.
Ключ не записывается в manifest или клиентский код. Затем закоммитьте manifest,
дождитесь автодеплоя и пересохраните виджет в VK. Если у карточки нет подходящего
загруженного изображения, используется компактный список без фотографий;
аватарки сообществ и старые фотографии с другим URL не подставляются.
В заголовке — «УЛЕТАЙ», даты фестиваля и число полных дней до старта,
рассчитанное при сохранении; во время и после фестиваля используется статус.
Для ежедневного обновления заголовка нужен серверный вызов `appWidgets.update`
с ключом этого приложения и правом `app_widget`; без него требуется пересохранение.
Расположение плиток определяет VK; общая ссылка открывает Mini App с карточками
и отдельными кнопками участников/билетов. Для нативного шаблона используются
только внутренние ссылки vk.com, как требует VK; внешние URL и `away.php` запрещены.
Ссылка «Все участники» показывает их общее число и открывает Mini App.
Данные шаблона фиксируются при установке;
после изменения состава нужно повторно открыть предпросмотр и сохранить.
Сама страница Mini App читает актуальные данные CMS при каждом открытии.
Токены не требуются для предпросмотра и не сохраняются на клиенте/сервере.
Для будущего фонового обновления понадобится новый ключ именно этого приложения
с правом `app_widget`; обычный токен сообщества этого права не предоставляет.

Документация: https://dev.vk.ru/ru/api/community-apps-widgets/getting-started,
https://dev.vk.ru/ru/reference/objects/app-widget,
https://dev.vk.ru/ru/bridge/VKWebAppShowCommunityWidgetPreviewBox.

Проверки, Expo web и Next.js CMS собираются на 147.45.235.170 под `gitlub-ci`,
Node 24.19.0, с ограничением 4 ГБ RAM и 150% CPU, отдельно от рабочих сайтов.
Production 212.193.26.91 получает готовый архив с SHA-256. Прежний
`deploy/release-deploy.sh` сохраняет переключение между портами, миграции,
uploads, уведомления, проверку карты/маршрутов и откат при неготовности релиза.

В Settings → Actions → Variables/Secrets параметры окружения production имеют
префикс `PRODUCTION_`. `PRODUCTION_DEPLOY_ENV` содержит исходный CMS .env;
одноимённые отдельные параметры переопределяют его значения. LASTFM_API_KEY
хранится в Secrets. Сохранены действующие ключи Web Push. SSH-ключи заменены
ограниченными ключами без passphrase; прежний SSH_KEY_PASSPHRASE больше не нужен.
BUILD_SSH_* соединяют runner с сервером сборки; PRODUCTION_SSH_* используются
заданиями синхронизации. Копия production-ключа также установлена у root сборщика.

Sync Last.fm запускается ежедневно в 01:00 UTC (04:00 МСК) и вручную.
Sync headliner web images запускается вручную. Оба workflow работают через
ограниченный SSH-вход на production и используют текущий активный CMS, локальную
MySQL и общий uploads. Туннель MySQL не требуется. Поддержаны dry_run, force,
limit. Общая блокировка синхронизации и переключения релиза предотвращает гонки.
При переносе задания проверяются в dry-run без изменения базы и изображений.

Обработчики: `/usr/local/sbin/gitlub-uletay-build` на сборщике и
`/usr/local/sbin/gitlub-uletay-production` на production. Целевые адреса и путь
закреплены в них; изменения инфраструктуры требуют обновить их вместе с Secrets.
Старые GitHub workflow отключаются после успешной проверки новых заданий.

Скрипты выпуска принимают прежнюю передачу из 22 полей и расширенную из 25
полей (`DB_PORT`, `VK_APP_ID`, `VK_REDIRECT_URI` перед SHA и ID выпуска).
Так можно обновить приложение до смены серверного обработчика. Если обработчик
ещё передаёт 22 поля, дополнительные настройки сохраняются из существующего
`cms/.env`; не удаляйте этот файл при обновлении.
