# Повторные рекомендации Google Play для 1.0.13 (32)

Проверено 17 сентября 2026 года по исходному опубликованному AAB
`release-archive/1.0.13/builds/uletay-1.0.13-32.aab`.
SHA-256: `2a62e053f8557defa2b174c1b2a6e1b061e4304dc9b8f61071d7c2a9c421989c`.
Использована встроенная карта R8
`BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map`,
а не карта от другой сборки. Выдержки сохранены в
`tmp/play-1.0.13-warning-mapping.json`.

## Что подтверждает новый отчёт

Замечания об отключённой оптимизации и отключённом оптимизированном удалении
ресурсов исчезли. Осталось требование обновить AGP до 9. Это согласуется со
встроенными метаданными AAB: AGP 8.13.2, R8 8.13.19, оптимизация и полный режим
включены, оптимизированное удаление ресурсов включено.

Предупреждения по Window API и декодированию не были устранены полностью.
Имена после R8 нельзя трактовать буквально: оптимизатор объединяет классы
и встраивает методы разных библиотек в один метод.

| Символ в отчёте | Источник и вывод |

Наличие декодера в библиотеке само по себе не доказывает утечку или загрузку
полноразмерного изображения в каждом случае. Равным образом наличие Glide
в приложении не доказывает, что все его загрузки проходят через Glide.

## Исправление загрузки обложек

В `patches/expo-audio/NotificationArtworkLoader.kt` подготовлен загрузчик,
использующий ту же Glide 5.0.5, что и expo-image. Он запрашивает изображение
в пределах 512 × 512 с сохранением пропорций, использует кеш Glide и ограничивает
ожидание 15 секундами. Отмена coroutine прерывает ожидание и освобождает запрос.
Для уведомления создаётся собственная копия ARGB: после освобождения Glide
не сможет повторно использовать её пиксели. Размер этой копии — не более 1 МиБ;
это не утверждение о максимуме общей памяти процесса или всего декодирования.

Патч применяется `scripts/patch-expo-audio-artwork.mjs` при `npm install` / EAS.
В package.json модуль expo-audio включён в Android `autolinking.buildFromSource`,
чтобы SDK 57 использовал исправленные исходники вместо готового исходного AAR.
Версия expo-audio проверяется явно; при обновлении зависимости требуется
пересмотр патча. Изменения только в node_modules без воспроизводимого патча
не считались бы исправлением.

Нативные проверки: `node scripts/test-android-artwork.mjs` после создания
Android prebuild; нужны JDK 17 и Android SDK (`JAVA_HOME`, `ANDROID_HOME`).
Проверяются большие альбомные и портретные картинки, владение пикселями после
освобождения Glide, повторный запрос, ошибка HTTP и отмена медленной загрузки.

## Ограничение обновления платформы

Expo SDK 57 рассчитан на React Native 0.86; поддержка AGP 9 появилась в следующем
поколении платформы. На дату проверки Expo 58 доступен как beta и включает
React Native 0.88 RC. Произвольная замена только AGP или React Native не является
поддерживаемой миграцией SDK 57.

В React Native 0.87 удалены старые методы StatusBar, однако `WindowUtil.kt`
версии 0.87.1 всё ещё содержит присваивания `statusBarColor`, `navigationBarColor`
и режимы DEFAULT/SHORT_EDGES. Поэтому даже обновление платформы нельзя заранее
называть гарантией исчезновения всех предупреждений Play. Проверять нужно
готовую сборку, интерфейс на поддерживаемых Android и новый отчёт магазина.
